# Do it(두잇) Widget 서비스 개발 기획서

- 문서 버전: 1.1
- 작성일: 2026-09-22
- 서비스명: Do it(두잇) Widget
- 주 사용 환경: macOS
- 메인 캐릭터: 보송이
- 목적: 직접 입력한 할 일, 기존 Notion 데이터베이스의 업무, Microsoft Teams 회의 일정을 하나의 데스크톱 위젯에서 확인하고 관리한다.
- 문서 범위: 제품 요구사항, 화면, 업무 규칙, 외부 연동, 데이터 모델, 구현 구조, 개발 순서, 인수 기준.
- 상태: 개발 시작용 제안안. 기존 Notion DB의 실제 속성과 Microsoft 계정 환경은 아직 확인하지 않았으며 아래 매핑과 기술 선택은 기본 설계안이다.

## 1. 제품 정의

다른 작업이나 인터넷 서핑을 하는 동안에도 지금 해야 할 일과 다음 일정을 잊지 않도록, 화면 한쪽에 작은 위젯을 상시 표시하는 개인 업무 관리 서비스다.

사용자는 앱에서 할 일을 직접 입력하거나 이미 사용 중인 Notion DB를 연결한다. 앱과 Notion 어느 쪽에서 수정하더라도 연결된 항목에 반영된다. Teams 회의는 Microsoft 365 캘린더에서 가져와 업무 시간 블록과 함께 하루 타임라인에 표시한다.

위젯은 접힘 상태를 기본으로 하며 필요한 정보부터 단계적으로 보여준다.

1. 평소에는 보송이와 대표 할 일의 체크박스·중요도·제목만 표시한다.
2. 회의 당일 시작 30분 전부터 회의 시간과 타이틀을 가장 먼저 표시한다.
3. hover 또는 키보드 포커스 시 오늘 남은 할 일 개수를 추가로 표시한다.
4. 펼치기를 클릭하면 전체 할 일 목록, 상세 설명, 오늘 타임라인을 확인할 수 있다.

### 1.1 해결할 문제

- Notion이나 캘린더를 직접 열어야 업무와 일정을 떠올릴 수 있다.
- 할 일과 회의가 다른 도구에 흩어져 있어 시간 배분이 어렵다.
- 중요한 업무와 단순히 시간이 임박한 업무를 구분하기 어렵다.
- 여러 도구에 같은 업무를 복사하면 완료 상태와 일정이 달라진다.

### 1.2 대표 사용 시나리오

오후 1시에 사용자가 ‘13:00~15:00 제안서 작성’을 시작한다. 브라우저에서 자료를 조사하는 동안 접힌 위젯에는 보송이와 ‘개중요 · 제안서 작성’이 보인다. 마우스를 올리면 ‘오늘 남은 할 일 4개’가 나타나고, 펼치기를 누르면 전체 목록과 타임라인이 열린다. 제안서의 체크박스를 선택하면 완료 처리되어 개수가 즉시 줄고 연결된 Notion 항목도 완료로 바뀐다. 15:30 회의가 있는 날에는 15:00부터 위젯에 ‘15:30–17:00 · 주간 회의’가 표시된다.

## 2. 기본 제품 결정 및 범위

### 2.1 개발 기본값

| 항목 | 기본 결정 | 이유 및 조정 조건 |
|---|---|---|
| 제품 형태 | 설치형 데스크톱 앱 + 항상 위에 표시되는 작은 창 | 일반 웹페이지로는 다른 앱 위 상시 노출을 안정적으로 충족하기 어렵다 |
| 지원 플랫폼 | macOS 우선 개발·배포 | Windows는 후속 확장, MVP 완료 조건에서 제외 |
| 사용자 단위 | 개인 사용자 | 팀 배정·공유 권한은 후속 범위 |
| Notion | 기존 DB 안의 데이터 소스 1개 연결 | 새 DB 생성이나 기존 구조 변경을 강제하지 않는다 |
| Microsoft | 업무/학교 계정의 본인 기본 캘린더 1개 | 공유·그룹 캘린더와 개인 계정은 후속 검증 |
| 일정 연동 방향 | Microsoft → 서비스 읽기 전용 | 회의 수정은 원본 캘린더에서 수행 |
| Notion 연동 방향 | 매핑 가능한 필드의 생성·조회·수정 양방향 | 원본 페이지 본문 전체 편집은 제외 |
| 기본 시간대 | OS 시간대 최초 감지, 설정에서 변경 | 저장 시 UTC와 원본 시간대 보존 |
| 동기화 방식 | MVP는 주기적 조회와 수동 새로고침 | 공개 웹훅 서버 없이 개인용 검증 가능 |
| 다중 기기 | MVP는 단일 기기 | 계정 기반 클라우드 동기화는 후속 범위 |

### 2.2 우선순위

| 우선순위 | 포함 기능 |
|---|---|
| P0: MVP 필수 | 위젯 상시 노출, 직접 입력/수정/완료, 중요도, 오늘 목록·타임라인, Notion 연결·속성 매핑·양방향 수정, Microsoft 일정 조회·회의 30분 전 위젯 안내, 접힘 기본·hover 개수·클릭 전체 보기, 체크박스 완료, 오프라인 캐시·재시도·충돌 처리 |
| P1: 개선 | 여러 DB/캘린더, 웹훅·증분 동기화, 타임라인 드래그 조정, 반복 할 일, 사용자 지정 필터, 클라우드 계정·여러 기기 |
| P2: 확장 | 모바일, 팀 협업, 업무 통계, 자동 시간 배치, AI 요약 |

MVP에서도 이미 캘린더에 있는 반복 회의의 개별 발생 일정은 지원한다. ‘반복 할 일 생성’은 별도 후속 기능이다. 회의 녹음·전사·채팅 수집·회의 생성/수정은 범위에 포함하지 않는다.

## 3. 핵심 개념과 업무 규칙

### 3.1 할 일과 일정 구분

- **할 일(Task)**: 완료 여부와 중요도가 있는 실행 항목. 시간 지정은 선택 사항이다.
- **업무 시간 블록(Task schedule)**: 할 일 하나에 지정한 시작·종료 시간. MVP는 할 일당 1개 블록.
- **회의 일정(Calendar event)**: Microsoft에서 가져온 시간 기반 이벤트. 할 일 완료 개수에 포함하지 않는다.
- **마감(Due)**: 언제까지 완료해야 하는지. 실제 작업 시간 블록과 별개다.
- **오늘 할 일(Planned date)**: 오늘 처리할 대상으로 지정한 날짜. 마감과 별도로 관리한다.

### 3.2 상태와 중요도

| 필드 | 값 | 규칙 |
|---|---|---|
| 상태 | todo / in_progress / done / canceled | done·canceled는 남은 개수 제외 |
| 중요도 | P1 개중요 / P2 챙겨두자 / P3 천처니 | 기본 P2, 색상 외 텍스트로도 구분 |
| 지연 여부 | 별도 계산값 | 마감이 지난 미완료 항목. 중요도를 자동 변경하지 않음 |
| 동기화 상태 | local_only / synced / pending / syncing / conflict / error / inaccessible | 업무 상태와 분리 |

중요도 네이밍 제안:

| 저장값 | 화면 이름 | 의미 | 표현 |
|---|---|---|---|
| P1 | 개중요 | 높음 · 먼저 챙겨야 하는 일 | 절제된 레드 텍스트 |
| P2 | 챙겨두자 | 보통 · 놓치지 않고 처리할 일 | 블루 텍스트 |
| P3 | 천처니 | 낮음 · 여유 있게 진행할 일 | 뉴트럴 그레이 텍스트 |

선택 메뉴에서는 ‘개중요 · 높음’처럼 의미를 함께 보여주고 위젯에서는 짧은 이름만 표시한다. ‘천처니’도 마감이 지나면 지연 표시를 제공한다. 내부 P1/P2/P3와 Notion 옵션 매핑은 유지하며 기존 DB 옵션 이름을 바꾸지 않는다.

시간이 끝났다는 이유만으로 할 일을 완료 처리하지 않는다. 할 일은 체크박스로 완료 여부를 관리한다. 체크하면 `done`과 `completed_at`을 기록하고, 체크 해제하면 `todo`로 되돌리며 완료 시각을 제거한다. 진행 중 표시는 상세 편집에서 관리한다. 회의가 끝나면 과거 일정으로 바뀌며 ‘완료’ 체크박스는 제공하지 않는다.

### 3.3 오늘 남은 할 일 계산

사용자 시간대에서 아래 조건 중 하나를 만족하는 활성 할 일을 ID 기준으로 중복 제거한 집합을 `today_tasks`로 정의한다.

- `planned_date`가 오늘.
- 업무 시간 블록이 오늘의 `[00:00, 다음 날 00:00)` 구간과 겹침.
- 마감일이 오늘이거나 이미 지남.

`remaining_count = today_tasks 중 상태가 todo 또는 in_progress인 개수`.

- 숨김·보관·접근 불가 상태는 제외하고 해당 상태를 별도 표시한다.
- 날짜 없는 미지정 업무는 ‘보관함 N개’에 표시하며 오늘 개수에는 넣지 않는다.
- ‘오늘로 지정’하면 즉시 오늘 개수에 포함한다.
- 날짜만 있는 마감은 해당 날짜가 끝난 뒤 지연으로 판단한다. 임의의 UTC 자정으로 변환하지 않는다.
- 총 활성 업무 개수는 상세 화면에서 따로 표시한다.
- 완료 표시와 개수 변화는 같은 로컬 트랜잭션으로 반영한다.

### 3.4 위젯 대표 할 일 선택

오늘의 미완료 할 일 중 다음 정렬 순서를 사용한다.

1. 현재 시간이 업무 시간 블록 안에 있는 항목.
2. 지연된 항목.
3. 중요도 P1 → P2 → P3.
4. 마감이 빠른 항목. 마감 없음은 뒤로.
5. 생성 시간이 빠른 항목, 마지막 동률은 ID.

완료된 항목은 제외한다. 사용자가 확인 중인 카드는 서버 응답마다 바꾸지 않고 완료·시간 경계 통과·사용자 새로고침 시 재선정한다. ‘목록 보기’에서 전체 오늘 할 일을 확인한다.

### 3.5 현재·다음 일정 계산

- 대상: 미완료 업무 시간 블록 + 취소되지 않고 참석 거절하지 않은 캘린더 일정.
- 현재 일정: `start <= now < end`. 여러 개면 ‘일정 겹침 N개’를 표시하고 시작 시간 순으로 펼친다.
- 다음 일정: `start > now` 중 가장 가까운 시작 시간. 같은 시각이면 회의를 먼저 표시하고 ‘외 N개’를 붙인다.
- 종일 일정은 별도 상단 영역에 표시하고 분 단위 카운트다운에서 제외한다.
- 펼친 타임라인에서 오늘 다음 일정이 없으면 캐시 범위 안의 가장 가까운 일정을 날짜와 함께 표시한다. 범위 밖은 ‘오늘 남은 일정 없음’으로 표시한다.
- 60초 이상 남으면 올림한 분, 60초 미만이면 ‘곧 시작’. 시작 시 현재 일정으로 이동한다.
- 일정 조회 기본 범위는 사용자 시간대 기준 어제부터 향후 14일까지. 갱신 실패 시 마지막 동기화 시각은 설정 > 연동 및 동기화 관리에 표시한다.

접힌 위젯의 회의 안내 노출은 위 계산과 별도로 7.1의 당일·시작 30분 전 조건을 적용한다. 펼친 타임라인은 안내 시점 전에도 조회된 일정을 모두 보여준다.

## 4. 화면 및 상호작용

### 4.1 화면 구성

| 화면 | 주요 내용·행동 |
|---|---|
| 온보딩 | 시간대 확인 → 직접 입력 시작 / Notion 연결 → Microsoft 선택 연결 → 위젯 배치 |
| 접힌 위젯 · 기본 | 보송이, 대표 할 일 체크박스·중요도·제목, 해당 시점의 회의 안내, 펼치기 |
| hover/포커스 위젯 | 접힌 내용 유지 + 오늘 남은 할 일 개수 |
| 펼친 패널 | 전체 할 일 체크리스트, 오늘/전체 전환, 완료 항목, 시간순 타임라인, 추가·설정 |
| 할 일 편집 | 제목, 짧은 설명, 상태, 중요도, 오늘 지정, 마감, 시간 블록, 저장 위치 |
| 설정 > 연동 및 동기화 관리 | 계정, DB·데이터 소스, 속성 매핑, 마지막 성공 시각, 대기 건수, 오류·충돌, 수동 동기화, 재연결·연결 해제 |
| 일반 설정 | 항상 위, 위치, 회의 안내 켜기/끄기, 시간대, 자동 시작, 내용 숨김 |
| 충돌 해결 | 마지막 공통 값·앱 값·Notion 값 비교, 필드별 선택 후 저장 |

### 4.2 위젯 상태와 와이어프레임

**접힘 · 기본**

```text
┌──────────────────────────────────────┐
│ [보송이] ☐ [개중요] 제안서 작성   ⌄  │
└──────────────────────────────────────┘
```

**회의 당일, 시작 30분 전부터**

```text
┌──────────────────────────────────────┐
│ [보송이] 15:30–17:00 · 주간 회의  ⌄  │
│          ☐ [개중요] 제안서 작성       │
└──────────────────────────────────────┘
```

**hover 또는 키보드 포커스**

```text
┌──────────────────────────────────────┐
│ [보송이] ☐ [개중요] 제안서 작성   ⌄  │
│          오늘 남은 할 일 4개          │
└──────────────────────────────────────┘
```

**클릭으로 펼침**

```text
┌──────────────────────────────────────┐
│ [보송이] Do it Widget         ⚙   ⌃  │
│ 15:30–17:00 · 주간 회의              │
│ 오늘 남은 할 일 4개                  │
│ [오늘] [전체]                        │
│ ☐ [개중요] 제안서 작성               │
│   고객 요구사항과 일정안을 정리해    │
│   내부 검토용 초안으로 공유하기      │
│ ☐ [챙겨두자] 견적 확인               │
│ ☐ [천처니] 참고 자료 정리            │
│ … 목록 스크롤로 모든 항목 확인       │
│ [완료한 일 보기]          [＋ 추가]  │
│ 오늘 타임라인                       │
│ 13:00–15:00 제안서 작성              │
│ 15:30–17:00 주간 회의                │
└──────────────────────────────────────┘
```

- 최초 실행·재실행 시 항상 접힘으로 시작한다. 펼침은 현재 세션의 일시적 상태다.
- 최초 위치는 주 디스플레이 작업 영역의 가로 중앙, macOS 메뉴바 아래 16px이다. 브라우저 탭과 본문을 과도하게 가리지 않는 360px 너비의 접힌 위젯을 기준으로 한다.
- 기본 너비 320px, 접힘 높이 64px 제안. 회의 행·hover 개수 행 추가 시 내용에 맞춰 확장한다. 펼침은 너비 360px, 최대 높이 560px 또는 화면 가용 높이 중 작은 값으로 제한하고 내부 스크롤한다.
- 접힘에는 설명·전체 개수·추가 버튼·동기화 문구를 상시 배치하지 않는다. 회의 시간과 제목은 안내 대상일 때 유지한다.
- hover 150ms 후 개수를 표시하고 포인터 이탈 200ms 후 숨긴다. 위치 기준점을 고정하고 확장된 영역도 hover 영역에 포함해 깜빡임을 방지한다.
- 위젯이 키보드 포커스를 받으면 hover와 같은 개수를 제공한다. 펼치기 버튼은 Enter/Space로 작동한다.
- 보송이 또는 펼치기 버튼 클릭 시 패널을 연다. 체크박스는 완료만 수행하고 펼치기 이벤트로 전파하지 않는다.
- 펼친 패널은 포인터가 떠나도 유지한다. 접기 버튼 또는 Escape로 닫는다. 항목 제목 클릭은 편집 패널을 연다.
- 펼치면 오늘 할 일을 모두 스크롤로 확인하고 ‘전체’에서 날짜 미지정·다른 날짜 업무까지 확인한다. 완료 항목은 ‘완료한 일 보기’로 펼쳐 체크를 해제할 수 있다.
- 펼친 할 일의 제목 1줄 + 설명 최대 2줄. 접힌 제목은 1줄 말줄임, 접근 가능한 전체 이름과 편집 패널 제공.
- AI 요약 없이 사용자의 짧은 설명을 사용한다. 설명이 없으면 제목만 표시한다.
- 새 회의 안내로 자동 펼침·포커스 이동을 하지 않는다. 체크 후 대표 할 일은 다음 대상으로 교체한다.
- 비조작 여백을 드래그 영역으로 사용하고 체크박스·보송이·버튼은 제외한다.
- 드래그를 끝낸 위치는 로컬 설정에 저장해 다음 실행에도 복원한다. 설정과 메뉴바에서 ‘상단 중앙으로 이동’을 제공한다.
- 기본 항상 위 표시. macOS 메뉴바에서 숨김·다시 표시·설정·종료 가능. 창 닫기는 숨김, 종료 메뉴는 프로세스 종료.
- 모니터 분리 시 보이는 영역으로 복귀하고 모니터 식별자·상대 좌표를 저장한다.
- macOS 전체 화면·Spaces·Mission Control·보안 화면 위 노출은 실제 기기에서 검증하고 지원 범위를 명시한다.
- 동기화 성공 시각·전송 대기·오류 상세는 접힘/hover/펼침 콘텐츠에 넣지 않는다. 필요한 경우 설정 아이콘에 작은 상태 점만 표시하고 상세는 설정에서 확인한다.

### 4.3 타임라인

```text
오늘 · 9월 22일
종일     프로젝트 마감일
13:00 ┌ 제안서 작성 [개중요] [Notion]
      │ 업무 시간 2시간
15:00 └
      · 비어 있는 시간 30분
15:30 ┌ 주간 회의 [Microsoft / Teams]
      │ 주간 업무 진행 상황 확인
17:00 └
시간 미지정: 견적 확인 · 회신 작성
```

30분 눈금과 현재 시각 선을 제공한다. 겹친 일정은 나란히 표시하고 좁은 폭에서는 겹침 묶음으로 펼친다. 자정을 넘는 일정은 날짜별로 잘라 그리되 동일 항목 ID를 유지한다. 제목·시간·중요도 외 상세 내용은 클릭해서 확인한다.

### 4.4 직접 입력

1. 위젯을 펼친 뒤 ‘추가’를 선택한다.
2. 제목은 필수, 나머지는 선택. 제목 1~200자, 짧은 설명 최대 500자, 푸시 리마인드 시각은 선택 사항이다.
3. 기본값은 todo, P2, 오늘 할 일. 날짜를 해제하면 보관함으로 이동한다.
4. 시간 블록을 지정하면 종료가 시작보다 뒤여야 한다. 자정 넘김은 날짜를 명시한다.
5. 저장 위치는 ‘앱만’ 또는 연결한 Notion. 최초 기본값은 앱만이고 이후 최근 선택을 기억한다.
6. 로컬에 즉시 저장한 뒤 Notion 대상으로 선택한 항목만 전송한다.

### 4.5 비주얼 디자인 가이드

디자인 방향은 사용자가 지정한 토스 같은 깔끔하고 군더더기 없는 정보 표현이다. 화면의 중심은 할 일과 회의이며, 보송이로 친근함을 더한다.

| 요소 | 기준 |
|---|---|
| 배경 | 퓨어 화이트 `#FFFFFF`. 위젯·패널·설정 모두 동일. 미색·아이보리·베이지·크림톤 제외 |
| 기본 글자 | `#191F28`, 보조 글자 `#6B7684` |
| 구분선 | `#E5E8EB`, 필요한 경계에만 1px |
| 액션 컬러 | `#2563EB`, 체크박스 선택·주요 액션에 제한적으로 사용 |
| 중요도 | 개중요: red-50 배경 / red-700 글씨, 챙겨두자: blue-50 / blue-700, 천처니: slate-100 / slate-600. 20px 높이의 rounded-full 뱃지 |
| 서체 | 로고는 `Paperlogy ExtraBold` 800, 나머지는 `Pretendard Variable`, 시스템 폰트 순서 |
| 글자 크기·굵기 | 대표 할 일 14px/500, 본문 13px/400, 보조 정보 12px/400, 패널 제목 16~20px/600 |
| 행간 | 본문 1.5, 짧은 제목·시간 1.4. 확대 시 고정 높이로 자르지 않음 |
| 자간 | 기본 `0em`, 제목도 동일. 과도한 압축·벌림 없음 |
| 간격 | 4px 단위, 요소 간 8px, 그룹 간 16px, 외곽 패딩 16px |
| 모서리·그림자 | 위젯 16px, 컨트롤 8px, `0 4px 20px rgba(0,0,0,0.08)` 정도의 약한 그림자 |
| 정보 구조 | 접힘은 핵심 1~2개, hover는 개수 추가, 클릭은 목록·타임라인. 카드 안에 카드를 겹치지 않음 |
| 모션 | 상태 전환 120~180ms, 반복 점멸·튀는 효과 없음. 동작 줄이기 설정 존중 |

Paperlogy ExtraBold와 Pretendard Variable은 앱에 포함해 오프라인에서도 동일하게 표시하며 배포 시 라이선스 고지를 확인한다. MVP는 화이트 테마를 기준으로 하고 다크 모드는 후속 범위로 둔다.

### 4.6 메인 캐릭터: 보송이

- 기존에 생성한 보송이를 공식 메인 캐릭터로 사용한다. 새 캐릭터로 대체하거나 외형을 임의로 재해석하지 않는다.
- 접힌 위젯 왼쪽에 32~40px, 펼친 패널 헤더에는 약 40px, 온보딩·빈 상태에는 80~120px로 배치한다.
- 캐릭터가 회의 제목·체크박스·본문을 가리지 않도록 독립 영역을 확보한다. 기본 위젯에서는 정적인 기본 포즈를 사용한다.
- 완료 후 짧은 반응은 기존에 사용 가능한 포즈가 있을 때만 적용한다. 없는 포즈는 구현 의존 항목으로 남긴다.
- 투명 배경과 Retina 해상도를 지원하고 이미지 바깥 여백을 조정한다. 보송이의 원래 색상은 보존하되 화면 배경은 흰색으로 유지한다.
- 클릭 가능한 보송이의 접근성 이름은 ‘할 일 펼치기/접기’로 제공한다.
- 승인된 보송이 idle 스프라이트의 첫 프레임을 추출해 앱에 연결했으며 40px와 72px 표시 크기에서 식별성을 검증한다.

## 5. Notion 연동 명세

### 5.1 연결과 기존 DB 존중

개인용 초기 구현은 사용자가 만든 internal connection 토큰으로 연결하고, 배포형 서비스에서는 OAuth public connection으로 전환한다. 선택한 페이지/DB에 접근 권한이 있어야 한다. 토큰·비밀키를 앱 소스나 렌더러에 넣지 않는다. [Notion 인증 문서](https://developers.notion.com/guides/get-started/authorization)

연결 흐름:

1. 인증 후 기존 DB URL 또는 접근 가능한 DB를 선택한다.
2. DB 내부 데이터 소스를 조회하고 여러 개면 사용자가 하나를 선택한다.
3. 속성 스키마를 읽어 매핑 초안을 제안한다.
4. 읽기/쓰기 가능 여부와 샘플 5개를 미리 보여준다.
5. 매핑 확정 후 페이지네이션으로 최초 수집한다.

기존 Notion 뷰의 필터·정렬이 API 조회에 자동 적용된다고 가정하지 않는다. 앱에서 가져올 조건을 별도로 정의한다. MVP 기본은 선택한 데이터 소스의 전체 활성 항목이며 공유 DB라면 담당자 필터를 설정할 수 있어야 한다.

### 5.2 속성 매핑

| 앱 필드 | 허용 Notion 속성 | 없거나 쓰기 불가능할 때 |
|---|---|---|
| 제목 | title | 필수, 매핑 전 연결 완료 불가 |
| 상태 | status / select / checkbox | 앱에만 저장, 양방향 미지원 표시 |
| 중요도 | select / number | 앱에만 저장 |
| 짧은 설명 | rich_text | 앱에만 저장, 페이지 본문은 변경하지 않음 |
| 오늘 지정 날짜 | date | 앱에만 저장 |
| 마감 | date | 앱에만 저장 |
| 업무 시간 블록 | date의 start/end | 앱에만 저장 |

- 이름 대신 속성 ID를 저장하고 화면에는 이름을 표시한다.
- 사용자가 실제 옵션을 매핑한다. 예: ‘대기→todo, 진행→in_progress, 완료→done’.
- checkbox는 체크=done, 해제=todo만 매핑한다. in_progress·canceled는 앱 상태로만 유지하며 재조회 시 임의로 지우지 않는다.
- 우선순위 숫자의 크고 작음은 추정하지 않고 P1/P2/P3와의 대응을 지정한다.
- 마감과 시간 블록을 같은 속성에 동시에 쓰도록 매핑하지 않는다.
- formula·rollup 등 계산 필드는 표시용으로만 지원하고 수정 불가를 표시한다.
- 미등록 status/select 옵션을 임의 생성하지 않는다. 매핑 오류는 해결을 요구한다.
- 속성 삭제·타입 변경 시 영향받는 필드 전송을 중지하고 재매핑 안내. 다른 필드는 유지한다.

Notion 페이지 속성 수정은 페이지 업데이트 API를 사용한다. 매핑된 변경 필드만 전송하고 본문과 다른 속성은 보존한다. [페이지 수정 API](https://developers.notion.com/reference/patch-page)

### 5.3 양방향 동작

| 사용자 행동 | 결과 |
|---|---|
| 앱에서 Notion 대상으로 새 할 일 저장 | 페이지 생성 후 로컬 Task와 페이지 ID 연결 |
| 앱에서 연결된 할 일 수정·완료 | 매핑 가능한 필드만 Notion에 반영 |
| Notion에서 항목 생성·수정 | 다음 동기화에서 앱 생성·갱신 |
| 앱에서 ‘위젯에서 숨기기’ | 로컬 숨김만 수행, 원본 유지 |
| Notion에서 휴지통 이동 | 확인 가능한 삭제 상태 수신 후 활성 목록에서 제외 |
| 권한 상실·404 | 삭제로 단정하지 않고 접근 불가 처리, 재연결 안내 |
| 앱만 저장한 할 일을 ‘Notion에 보내기’ | 기존 Task에 연결 추가, 복제 Task 생성 금지 |

MVP에서는 앱에서 원본 Notion 페이지를 삭제하는 동작을 제공하지 않는다. 앱 전용 항목은 로컬 보관·복구가 가능하다.

### 5.4 동기화와 충돌

- 앱이 실행 중이면 60초 주기로 변경 조회. 최초 로딩·수동 새로고침·절전 복귀에도 수행.
- 주기는 제품 기본값이며 제공자 호출 제한·DB 크기에 따라 조정한다. 마지막 성공 시각을 설정 > 연동 및 동기화 관리에 표시한다.
- 페이지네이션을 끝까지 처리하고, 시간 기반 변경 조회에는 2분 겹침 구간을 사용해 누락을 줄인다.
- 삭제·이동·필터 이탈 검출을 위해 앱 실행 시 및 실행 중 30분마다 전체 ID 대조를 수행한다. 조회 실패를 삭제로 해석하지 않는다.
- 로컬 편집과 Outbox 등록은 동일 트랜잭션. 실패해도 로컬 편집을 잃지 않는다.
- 같은 항목은 직렬 전송하고 최신 편집을 합친다. 원격 페이지 ID에 고유 제약을 적용한다.
- 기준 스냅샷 B, 로컬 L, 원격 R을 필드별 비교한다. L만 바뀌면 전송, R만 바뀌면 반영, 서로 다른 필드가 바뀌면 병합한다.
- 같은 필드가 양쪽에서 다르게 바뀌면 자동 덮어쓰기 없이 conflict 상태로 보존한다. 사용자가 앱 값/Notion 값을 선택한다.
- 원격 쓰기 직전 최신 값을 다시 읽고, 쓰기 뒤 다시 확인한다. Notion에 필드 단위 원자적 조건부 갱신이 있다고 가정하지 않는다. 읽기와 쓰기 사이의 경합은 완전히 제거할 수 없으므로 스냅샷과 변경 이력으로 복구 가능하게 한다.
- 완료와 제목 등 독립 변경은 병합 가능하지만, 원격 삭제와 로컬 편집 충돌은 원격 복원 없이 사용자가 앱 전용 사본으로 보존하도록 한다.
- HTTP 429는 Retry-After 존중, 5xx·네트워크 오류는 지수 백오프와 jitter 적용. 401은 인증 갱신/재연결, 403은 권한 확인, 매핑 오류는 해당 항목 중지.
- 페이지 생성 요청의 응답이 유실되면 무조건 재생성하지 않는다. `unknown_result`로 두고 원격 후보 확인 후 연결하거나 사용자가 재생성을 선택한다. 제공자의 멱등성 지원을 검증하지 않은 상태에서 자동 중복 방지를 보장하지 않는다.

P1에서는 웹훅으로 변경을 감지하고 최신 객체를 재조회한다. 중복·지연 이벤트에 대비해 이벤트 ID 중복 제거와 정기 대조를 유지한다. [Notion 웹훅 문서](https://developers.notion.com/reference/webhooks)

## 6. Microsoft·Teams 일정 연동

### 6.1 연동 원칙

Teams 화면을 스크래핑하지 않고 Microsoft Graph로 본인 캘린더의 일정을 읽는다. `calendarView`는 지정 구간의 단일 일정과 반복 일정 발생·예외를 조회하는 기반으로 사용한다. [calendarView API](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview?view=graph-rest-1.0)

이벤트의 `isOnlineMeeting`, `onlineMeetingProvider`로 Teams 회의를 식별하고 제목·시간으로 안내한다. 캘린더에 등록되지 않은 통화나 접근 권한이 없는 회의까지 수집한다고 가정하지 않는다. [이벤트 리소스](https://learn.microsoft.com/en-us/graph/api/resources/event?view=graph-rest-1.0)

### 6.2 인증과 조회

- Entra 앱 등록 후 시스템 브라우저 OAuth 로그인. 데스크톱 공개 클라이언트는 authorization code + PKCE를 사용하고 client secret을 내장하지 않는다.
- MVP 대상은 업무/학교 계정과 Exchange Online 사서함이 있는 사용자.
- 기본 요청 권한은 `openid`, `profile`, `offline_access`, 위임된 `Calendars.Read`.
- 일정 읽기만을 위해 메시지·채팅·녹음 접근 권한을 요청하지 않는다.
- 조직 정책에 따라 사용자 동의가 차단되거나 관리자 승인이 필요할 수 있다. 이 경우 직접 입력·Notion 기능은 계속 사용 가능.
- 응답 페이지네이션을 모두 처리하고 원본 시간대·시작·종료·취소·참석 응답·종일 여부를 저장한다.
- MVP는 60초 주기 구간 재조회. P1에서 고정 조회 구간별 delta token을 저장하고 구간 변경 시 초기화한다. [이벤트 증분 조회](https://learn.microsoft.com/en-us/graph/delta-query-events)
- 필요한 캘린더 권한의 계정별 지원 범위는 구현 시 등록 설정과 함께 검증한다. [Graph 권한 문서](https://learn.microsoft.com/en-us/graph/permissions-reference)

### 6.3 일정 처리 규칙

- 원본 제목·시간은 읽기 전용. ‘원본 열기’로 Microsoft 화면에서 편집한다.
- 회의 중요도는 앱 전용 오버라이드로 지정 가능하며 Microsoft에는 쓰지 않는다. 기본 P2.
- 취소된 일정과 참석 거절 일정은 기본 타임라인에서 제외한다. 미응답·미정은 배지로 구분한다.
- 시리즈 전체와 각 발생 일정을 중복 표시하지 않는다. 반복 일정의 수정·취소는 해당 발생 건에 반영한다.
- 외부 이벤트 ID와 캘린더 ID로 중복 제거한다. 제목과 시간만으로 Notion 업무와 자동 병합하지 않는다.
- 회의 참여 버튼·참여 링크 수집은 MVP에서 제외한다. 원본 열기는 펼친 일정의 상세 화면에만 둔다.
- 연결 해제 시 회의 캐시와 위젯 안내를 제거한다. 앱 할 일은 유지한다.

## 7. 알림·오프라인·빈 상태

### 7.1 회의 30분 전 위젯 안내

- 회의 당일, 시작 30분 전부터 접힌 위젯에서도 회의 시작·종료 시간과 타이틀을 보여준다. 예: `15:30–17:00 · 주간 회의`.
- 노출 조건: 사용자 시간대에서 시작 날짜가 오늘이고 `start - 30분 <= now < end`인 회의. 시작 전에는 ‘회의 예정’, 시작 후에는 ‘회의 중’ 의미를 접근성 이름으로도 제공한다.
- 회의가 다음 날 00:10에 시작한다면 전날에는 안내하지 않고 당일 00:00부터 표시한다. 이미 시작한 회의가 자정을 넘으면 종료 시까지 유지한다.
- 당일 회의라도 30분보다 많이 남았으면 접힌 위젯에는 안내하지 않는다. 펼친 타임라인에서는 미리 확인 가능하다.
- 종료·취소·참석 거절 시 제거한다. 시작 시간이 변경되면 노출 구간을 즉시 재계산한다.
- 진행 중 회의가 있으면 먼저 표시하고, 없으면 가장 가까운 예정 회의를 표시한다. 여러 건이면 ‘외 N개’로 묶고 펼친 패널에서 전부 확인한다.
- 종일 일정은 회의 사전 안내 대상에서 제외한다. 시간대와 절전 복귀 시 현재 시각으로 재계산하며 종료한 회의를 뒤늦게 알리지 않는다.
- 10분 전 토스트, OS 푸시, Teams 참여 버튼은 제공하지 않는다. 업무 시간 블록의 별도 토스트도 MVP 범위에서 제외한다.
- 앱이 실행 중일 때 위젯 표시로 안내한다. 종료 중 안내는 보장하지 않으며 OS 알림 권한은 요청하지 않는다.
- 내용 숨김 모드에서는 회의 타이틀을 ‘회의 예정’ 또는 ‘회의 중’으로 대체하고 시간만 유지한다.

### 7.2 할 일 푸시 리마인드

- 할 일을 추가할 때 사용자가 미래 시각을 선택하면 macOS 로컬 알림을 예약한다. 리마인드가 없는 할 일도 만들 수 있다.
- 알림 제목은 `Do it Widget · 할 일 리마인드`, 본문은 할 일 제목이다. 내용 숨김 모드에서는 일반 안내 문구로 대체한다.
- 알림을 클릭하면 위젯을 표시한다. 완료한 할 일의 예약은 즉시 취소하고 완료를 되돌리면 아직 미래인 예약만 복구한다.
- 앱 시작 시 미완료 할 일의 미래 리마인드를 다시 예약한다. 24일보다 먼 일정도 하루 단위로 재확인해 장기 타이머 제한으로 누락되지 않게 한다.
- 설정에서 모든 할 일 리마인드를 끄거나 다시 켤 수 있다. OS 알림 권한이 차단된 경우 설정에서 허용하도록 안내하는 기능은 배포 패키징 단계에서 추가한다.
- 앱 프로세스가 완전히 종료된 동안의 알림은 MVP에서 보장하지 않는다. 로그인 시 자동 실행을 권장하며, 후속 버전에서 시스템 예약 방식 적용을 검토한다.

### 7.3 상태별 표시

| 상황 | 표시와 동작 |
|---|---|
| 할 일 없음 | ‘오늘 등록된 할 일이 없어요’ + 추가 |
| 오늘 전부 완료 | ‘오늘 할 일을 모두 마쳤어요’ + 다음 일정 유지 |
| 다음 일정 없음 | ‘오늘 남은 일정 없음’ |
| 인터넷 끊김 | 캐시 유지, 설정 > 연동 및 동기화 관리에 ‘오프라인 · 변경사항 전송 대기 N건’ |
| 연동 오류 | 설정에서 마지막 성공 시각·재시도 또는 재연결 버튼 |
| 충돌 | 설정에서 ‘확인이 필요한 변경 N건’, 값 선택 화면으로 이동 |
| 권한 상실 | 접근 불가 표시, 해당 원본에 쓰기 중단 |
| 첫 동기화 중 | 로딩 + 앱 전용 할 일 입력은 가능 |

오프라인에서도 직접 입력·수정·완료가 가능하다. 연결된 항목의 전송 대기는 설정에서 표시하고 연결 복구 후 현재 원격 값과 비교하여 동기화한다.

## 8. 기술 구조 제안

### 8.1 개인용 MVP

```text
[Electron 위젯 / 관리 패널: React + TypeScript]
                     │ 제한된 IPC
[Electron Main: 도메인 서비스 / 스케줄러 / 연동 어댑터]
          ├── SQLite: Task / Event / Outbox / Snapshot
          ├── OS 보안 저장소: 외부 서비스 토큰
          ├── Notion API
          └── Microsoft Graph API
```

Electron은 일반 창의 항상 위 설정과 플랫폼별 창 제어를 제공하므로 후보로 선택한다. 전체 화면·작업 공간별 노출은 별도 검증 대상이다. [Electron BrowserWindow 문서](https://www.electronjs.org/docs/latest/api/browser-window)

- React·TypeScript: 위젯과 관리 패널 UI. Electron Main만 DB·토큰·외부 API에 접근.
- SQLite: 로컬 데이터와 Outbox의 트랜잭션 저장.
- `contextIsolation`과 sandbox 활성화, renderer의 Node 직접 접근 비활성화. IPC 입력 스키마 검사.
- 렌더러는 로컬 번들만 로딩. Notion 본문 등 외부 HTML을 실행하지 않는다.
- 외부 링크는 검증한 HTTPS URL만 시스템 브라우저로 연다. 임의 프로토콜 실행 금지.
- macOS 설치 패키지, 서명·공증, 업데이트 채널은 배포 단계에서 구성.
- 버전은 구현 착수 시 호환되는 안정 버전으로 고정하고 잠금 파일을 관리한다.

### 8.2 공개 서비스 확장

Notion OAuth client secret을 보관하고 토큰 교환을 수행할 최소 인증 서버를 추가한다. 서버와 데스크톱 간 로그인 핸드오프는 일회용 코드와 state 검증을 적용한다. 공개 웹훅 수신·여러 기기 동기화가 필요해지면 사용자별 데이터 저장소와 작업 큐를 확장한다. 개인용 로컬 토큰 방식과 공개 서비스 OAuth 방식을 혼합하지 않는다.

## 9. 데이터 모델

모든 로컬 ID는 UUID. 시간값은 UTC instant와 필요한 원본 시간대, 날짜 전용 값은 `YYYY-MM-DD`로 구분한다.

| 엔터티 | 주요 필드 |
|---|---|
| Task | id, title, summary, status, priority, planned_date, due_date, due_at, schedule_start_at, schedule_end_at, schedule_timezone, completed_at, hidden_at, archived_at, revision, created_at, updated_at |
| ExternalLink | id, task_id, connection_id, provider, container_id, external_id, external_url, remote_updated_at, sync_state, last_synced_at |
| CalendarEvent | id, connection_id, calendar_id, external_id, series_master_id, occurrence_start_at, title, start_at, end_at, timezone, is_all_day, local_start_date, local_end_date_exclusive, is_canceled, response_status, web_url, app_priority, remote_updated_at |
| Connection | id, provider, account_label, external_account_id, container_id, auth_secret_ref, state, last_success_at, last_error_code |
| PropertyMapping | connection_id, app_field, notion_property_id, property_type, value_mapping_json, writable |
| SyncSnapshot | external_link_id, normalized_fields_json, observed_remote_updated_at, updated_at |
| Outbox | id, operation_id, entity_id, connection_id, operation_type, patch_json, base_snapshot_json, state, attempts, next_retry_at, last_error |
| Conflict | id, entity_id, field, base_value, local_value, remote_value, resolved_at |
| SyncCursor | connection_id, scope, cursor_json, window_start, window_end, last_reconciled_at |
| WidgetSettings | timezone, bounds_json, always_on_top, default_collapsed=true, theme=light, privacy_mode, meeting_notice_enabled=true, meeting_notice_lead_minutes=30, auto_launch |

제약 및 인덱스:

- `ExternalLink(connection_id, container_id, external_id)` UNIQUE.
- `CalendarEvent(connection_id, calendar_id, external_id)` UNIQUE.
- `Outbox.operation_id` UNIQUE. 앱 내부 중복 방지용이며 외부 API의 멱등성을 보장하지 않는다.
- Task의 `status, planned_date`, `due_at`, Event의 `start_at, end_at`에 인덱스 생성.
- `due_date`와 `due_at`은 동시에 설정하지 않는다. 시간 블록은 시작·종료 모두 필수다.
- 연동하지 않은 Task에는 ExternalLink가 없다. Notion에서 가져온 Task도 로컬 전용 필드를 유지한다.

## 10. 앱 내부 인터페이스

네트워크 서버 없이도 아래 도메인 계약을 IPC로 구현한다. 모든 결과는 검증된 DTO로 반환하며 실패 형식은 `{ code, message, retryable, details }`로 통일한다.

| 명령/조회 | 입력 | 결과·정책 |
|---|---|---|
| tasks.create | title, summary?, priority?, plannedDate?, due?, schedule?, destination, operationId | Task 반환, 로컬 저장과 Outbox 동시 생성 |
| tasks.update | id, expectedRevision, patch, operationId | 새 revision 반환. 오래된 revision이면 충돌 반환 |
| tasks.complete | id, expectedRevision, completed, operationId | 완료/되돌리기, 개수 함께 갱신 |
| tasks.archive | id | 앱 전용 보관 또는 연결 항목 로컬 숨김 |
| dashboard.get | localDate, timezone | 현재/다음 일정, 안내 대상 회의, 남은 개수, 대표 할 일 |
| timeline.list | from, to, timezone | 업무 블록·회의·종일 일정 |
| connections.connect | provider, 인증 흐름 결과 | Connection 생성, 비밀값은 응답에서 제외 |
| notion.previewMapping | connectionId, dataSourceId | 속성·샘플·쓰기 지원 여부 |
| notion.saveMapping | connectionId, mappings | 검증 후 저장 |
| sync.status | connectionId? | 설정용 마지막 성공 시각·대기 건수·오류·충돌 반환 |
| sync.run | connectionId | 중복 실행 병합, 상태 이벤트 발행 |
| conflicts.resolve | conflictId, selectedValue | 최신 원격 재확인 후 수정 재시도 |
| connections.disconnect | connectionId, pendingChangePolicy | 대기 수정 보존/폐기 선택 후 토큰 제거 |

상태 이벤트는 `task.changed`, `calendar.changed`, `sync.changed`, `settings.changed`로 제한한다. 위젯과 편집 패널은 같은 데이터 스토어를 구독하여 개수·카드·타임라인이 서로 다르게 보이지 않게 한다.

## 11. 개인정보·품질 요구사항

- 토큰은 macOS Keychain에 보관하고 DB에는 참조만 저장한다.
- 로그에는 제목·설명·외부 URL·토큰을 남기지 않는다. 오류 코드와 익명화된 내부 ID만 사용한다.
- 화면 공유 시 사용자가 한 번에 제목·설명을 가리는 ‘내용 숨김’을 제공한다. 공유 앱 자동 감지는 MVP 범위 밖이다.
- 연결 해제 시 토큰을 지우고 원본은 보존한다. Notion 캐시를 앱 전용 사본으로 남길지는 사용자가 선택한다.
- 대기 중인 로컬 수정이 있으면 해제 화면에서 개수와 보존·폐기 선택을 보여준다.
- 앱 데이터 전체 삭제는 별도 명시적 동작으로 제공한다. 외부 원본 삭제와 구분한다.
- 키보드 탐색, 접근성 이름, 포커스 표시, 중요도 텍스트, 충분한 명암 대비를 제공한다.
- 비활성 위젯에서 불필요한 초 단위 렌더링을 피하고 시간 경계에 맞춰 갱신한다.

### 11.1 검증 목표

아래 수치는 제품 목표이며 성능 보장이 아니다. 기준 기기·OS·샘플 데이터로 측정한다.

## 14. 실제 개발 전 확정할 사항

답이 정해지기 전까지는 2장의 기본값으로 개발할 수 있다. 아래 중 외부 연동 관련 항목은 해당 연동 구현 전에 확인한다.

| 확인 사항 | 기본안 | 확인 시점 |
|---|---|---|
| 주 사용 OS | macOS 확정, 지원할 최소 버전·CPU 아키텍처 확인 | 단계 0 |
| 보송이 원본 | 기존 생성 이미지 사용, 실제 파일·사용 가능 포즈 확인 | UI 구현 전 |
| 개인용/공개 서비스 | 개인용 로컬 MVP 후 공개 OAuth 확장 | 인증 구현 전 |
| 기존 DB 속성·상태·중요도 옵션 | 자동 추정 후 사용자 매핑 | Notion 연결 시 |
| 공동 DB에서 본인 업무 구분 방법 | 담당자 필터, 없으면 전체 | 최초 가져오기 전 |
| M365 계정 및 조직 동의 정책 | 본인 기본 캘린더 읽기 | Microsoft 연동 전 |
| 기존 날짜 속성이 의미하는 것 | 마감과 실제 작업 시간을 분리 | 속성 매핑 시 |
| 오늘 남은 개수에 지연 업무 포함 여부 | 포함 | 첫 사용 검증 |
